# MaAS reproduction 修改日志（2026-09-17）

## 修改范围

本轮以原始源码 `MaAS-main/maas/ext/maas` 为行为基准，处理审查项 1、2、3、6、7、8、9、10。修改只落在 `applications/maas_reproduction` 内，没有修改 MASFactory 公共 `RootGraph`、`Loop` 或其他 application。

本轮明确不处理 GSM8K 解析语义、HumanEval 执行安全、`max_iterations`、Evaluator 异常详情、`tiktoken` 可选依赖和 P2 的 MASFactory 私有成员访问问题。DatasetRunner 的 checkpoint 生命周期是独立问题；工作区已有相关修改和测试，本轮未重写该实现。

## 已采纳修改

### 1. Controller 累计概率采样

- 在 `maas_reproduction/models/controller.py` 中加入与原 MaAS `models/utils.py::sample_operators` 同构的实现。
- 按当前剩余概率执行 `torch.multinomial`，采样后移除该 index，按采样顺序累计原始概率，累计达到 `OPERATOR_SELECTION_THRESHOLD == 0.3` 时停止。
- 空选择保持 `argmax` fallback。
- policy log probability 继续使用原始 `log_softmax` 中最终 selected indices 的和；没有改成重归一化后的条件采样概率。
- 下一层 `prev_operators` 使用完成首层修正和重排后的 indices。

### 2. 首层 Generate 语义

- 首层选到 `EarlyStop` 时替换为精确 `Generate` 并应用原始 `-1.5` 调整。
- 未选到任何 generate-family operator 时强制使用精确 `Generate`。
- 已选到 `Generate`/`GenerateCoT` 等 generate-family operator、但它不在首位时，同时重排名称和 indices，再计算 log probability 和下一层输入。
- `RoutePlannerNode` 的 flatten 逻辑同步采用相同规则，避免 controller 输出在 graph 层被二次改写成不同 route。
- 正式 catalog 必须包含精确 `Generate`；缺失时视为配置错误。未采用原代码的 index 0 静默 fallback，避免名称与实际 operator index 不一致。

### 3. 默认计算设备

- Controller 默认设备恢复为 `cuda if available else cpu`。
- 所有 policy 子模块创建完成后调用 `self.to(self.device)`。
- bootstrap 使用同一个 device 创建 embedding provider、operator embeddings 和 controller。
- optimizer 在 controller 完成设备迁移后创建，确保其绑定最终参数对象。

### 4. MATH 等价判断

- `benchmarks/math.py` 恢复原实现的符号判断链：直接/数值判断后，依次尝试 `parse_latex`、`parse_expr`，再执行 `simplify(a - b)` 和 `N(a)`/`N(b)` 数值近似 fallback。
- 在根 `pyproject.toml`、根 `requirements.txt` 和 `uv.lock` 中加入并锁定正式依赖 `sympy==1.13.1`，与原 MaAS 依赖版本一致。
- SymPy 仍在评分路径中懒加载；仅缺少 SymPy 时抛出明确的 `RuntimeError`，解析失败仍按 benchmark 规则返回 0 分。
- 没有修改 `BaseBenchmark.evaluate()` 的接口或异常边界。

### 5. MultiGenerateCoT 候选上限

- adapter 仍固定调用三次。
- 每次调用优先取 `result.solution`，否则最多取 `result.candidates[0]`。
- 不再展开一次调用返回的整个 candidates 列表，因此总候选数最多为 3。

### 6. ScEnsemble 失败语义

- 空候选、非法 letter 和 adapter 异常均返回结构化 `status="failed"`。
- 失败结果的 `solution` 为 `None`，不再把 `candidates[0]` 伪装成模型选择。
- 错误类型和文本保存在 metadata 中；异常仍不穿透 graph 边界。

### 7. InputSplitNode 属性隔离

- 显式设置 `pull_keys={}`、`push_keys={}`，阻止节点隐式拉取或回写 RootGraph 的全部 attribute store。

### 8. RootGraph invocation 隔离

- 在 reproduction 的 `workflow.py` 中增加局部 `MaASRootGraph`，没有修改 MASFactory 通用类。
- build 完成后保存合法的初始 attributes 快照；每次 `invoke()` 前恢复该快照，再由父类合并本次 invocation attributes。
- 没有使用无边界的 `clear()`，构建阶段或运行时初始化的合法属性会被保留，仅上一样本的 invocation overlay 被丢弃。

### 9. OperatorDispatchLoop 状态隔离

- 每次 `_forward()` 开始先删除 loop-local 旧 `dispatch_state`。
- 本次 state 非空时再写入；本次 state 为空时 store 中保持不存在。
- 没有扩大 `Loop.reset_gate()` 的公共职责。
