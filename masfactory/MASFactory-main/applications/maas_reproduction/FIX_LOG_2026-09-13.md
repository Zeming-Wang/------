# MaAS reproduction 修复记录

## 本次修复

### 1. 修复真实模型 token usage 和 cost 统计

- 文件：`maas_reproduction/runtime/bootstrap.py`
- 原因：adapter 只读 `response["usage"]`；MASFactory `OpenAIModel` 实际把 usage 累计到 `model.token_tracker`。
- 改动：调用前后读取 `total_input_usage` / `total_output_usage`，优先使用 provider usage，缺失时使用 tracker 增量，并把 token usage 放入 operator metadata。
- 删除：`total_tokens / 10000.0` 伪成本计算。
- 价格来源：`ModelSettings.input_cost_per_1k_tokens` 和 `output_cost_per_1k_tokens`。

### 2. 未配置价格时禁止伪造可靠成本

- 文件：`maas_reproduction/runtime/settings.py`
- 文件：`assets/config/models.json`
- 文件：`maas_reproduction/adapters/cost_tracker.py`
- 改动：增加显式 input/output 每 1K token 价格；默认均为 `null`。
- 行为：价格缺失时 `cost_reliable=False`，错误为 `model pricing is not configured; set input/output cost per 1k tokens`，训练 signal 会跳过更新。
- 目的：不能把 `cost_delta=0.0` 当作真实 provider 成本，也不能用未声明价格继续训练。

### 3. 修复 utility 丢失

- 文件：`components/loss_update_node.py`
- 原因：`BatchAccumulator.add()` 返回 optimizer/loss 元数据，但 `LossUpdateNode` 直接返回该字典，丢失 `TrainingSignal.utility`。
- 改动：复制 accumulator 返回值并补回 `update_result["utility"] = signal.utility`。
- utility 公式未改变：`score - 3.0 * cost_delta`。

### 4. 回归测试

- 文件：`tests/unit/test_task7_finalize_and_cost.py`
  - 新增无价格的零成本不能被视为可靠成本的测试。
- 文件：`tests/unit/test_loss_update_metadata.py`
  - 新增 optimizer step 后 utility 必须保留的测试。
  - 新增成本可靠性错误必须出现在公开 `failure_detail` 的测试。

### 5. 暴露成本配置错误

- 文件：`components/sample_result_node.py`
- 原因：架构结果已经保存 `execution_metadata.cost_error`，但公开结果只读取 `error_state`，导致 `failure_source=infrastructure` 时 `failure_detail=None`。
- 改动：优先把安全的 `cost_error` 放入 `failure_detail`，最多 500 字符。

### 6. 保留 recoverable operator 的来源

- 文件：`components/architecture_exec_graph/components/finalize_architecture_result_node.py`
- 原因：`DispatchState.error_state` 存在时，原逻辑仍可能输出 `failure_source=None`。
- 改动：存在执行错误状态且没有更具体来源时，明确标记为 `route_execution`。
- 文件：`components/sample_result_node.py`
- 改动：错误详情现在还包含安全的 `operator_name` 和 `status`，避免出现只有 `recoverable_failure`、没有原因的结果。

对应回归测试补充了可靠 cost tracker，避免测试中的 `cost tracker unavailable` 覆盖被验证的 operator 错误详情。

最新相关测试结果：`7 passed`。

### 7. 修复 EarlyStop 控制标记误入 InvalidOperatorNode

- 文件：`components/operator_dispatch_loop/workflow.py`
- 现象：真实运行出现 `EarlyStop: invalid_operator`。
- 根因：`RoutePlanner` 会保留后续层的 EarlyStop 控制标记，但 Loop 只为 registry operator 建边，EarlyStop 落入 invalid 分支。
- 改动：在 Loop 内新增 `early_stop_control` 控制节点，将标记转换为 `OperatorResult("EarlyStop", "control")` 并设置 `termination_requested=True`；invalid 分支明确排除 EarlyStop。
- 没有把 EarlyStop 加入普通 operator registry，也没有调用 EarlyStop operator。
- 新增回归测试，确认 Loop 存在控制节点且 registry 不包含 EarlyStop。

### 8. 修复 EarlyStop control 被误记为执行失败

- 文件：`components/operator_dispatch_loop/components/state_reducer_node.py`
- 现象：控制分支已生效，但结果仍为 `recoverable_failure`，详情为 `EarlyStop: control`。
- 根因：StateReducer 把所有非 `success/ok/completed` 状态都写入 `error_state`。
- 改动：仅对 `EarlyStop + control` 豁免错误记录；仍设置 `termination_requested=True`，但不设置 `error_state`。
- 预期：正常 EarlyStop 终止不再产生 `route_execution` 或 `recoverable_failure`。

## [2026-09-14] Programmer 子链路失败 (recoverable_failure) 诊断记录

### 1. 问题现象
- **表现**：运行 MATH 数据集时，第 2 题状态为 `recoverable_failure`，最终虽然通过 fallback 拿到 1.0 分，但节点提示 `Programmer: failed`。
- **影响**：导致 Token 消耗增加（成本上升 41%），且在强化学习训练中会向该路由发送负面惩罚信号。

### 2. 根因分析 (Root Cause)
1. **未注入 CodeExecutor**：
   - 位置：`applications/maas_reproduction/maas_reproduction/runtime/bootstrap.py`
   - 原因：`registry` 中只注入了 `programmer=adapter`（用于文本生成），未创建及传入 `CodeExecutor` 实例，导致 `ProgrammerExecutionNode` 发现执行器为 `None` 时抛出异常。
2. **Adapter 输出格式与代码解析器冲突**：
   - 位置：`bootstrap.py` 的 `adapter()` 函数
   - 原因：`adapter` 返回的是包含自然语言解释的文本，而 `CodeParseNode` 校验强制要求代码中含有 `def solve():` 函数。

### 3. 待修复项 (Action Items)
- [ ] 在 `bootstrap.py` 中创建并注入适配 `invoke()` 接口的 `CodeExecutor`。
- [ ] 为 `Programmer` 算子单独设计/改造 `adapter` 的 Prompt 指令，强制要求输出带 `def solve():` 的 Python 代码。


## [2026-09-14] ArtifactStore 敏感词脱敏校验误杀 (ValueError)

### 1. 问题现象
- **报错**：`ValueError: forbidden private data in artifact`
- **位置**：`applications/maas_reproduction/maas_reproduction/adapters/artifact_store.py` 第 12 行 `_write()` 方法
- **影响**：程序在完成题目计算准备保存 `sample_0.json` 时被中断，无法持久化测试结果。

### 2. 根因分析 (Root Cause)
- **硬编码子串匹配**：检查规则使用 `key in text.lower()` 对序列化后的 JSON 进行全局文本搜索（`forbidden = ("expected_answer", "api_key", "prompt")`）。
- **正常统计字段被误杀**：在 `bootstrap.py` 中记录 Token 开销时写入了 `"prompt_tokens"` 字典项，由于字符串 `"prompt"` 包含了在 `"prompt_tokens"` 中，导致正常使用统计数据触发脱敏拦截。

### 3. 修复方案 (Fix)
- **修复逻辑**：在进行敏感词搜索前，优先将文本中的 `"prompt_tokens"` 替换为无关子串（如 `"token_usage"`），避免全文搜索误杀。
- **状态**：已在 `artifact_store.py` 修复，待重新调试验证。
